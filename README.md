# مجمع طيبة تكنولوجي — الموقع ولوحة التحكم

موقع تعريفي عربي (RTL) لمجمع تقني، مع لوحة تحكم إدارية آمنة لإدارة الأقسام وطلبات التقديم والأخبار (بما فيها الصور المرفوعة وروابط الفيديو) والمحتوى والبيانات التجريبية.

- **الواجهة العامة ولوحة التحكم:** React 19 + Vite مع توجيه من جانب العميل (React Router)، وحركات مبنية على CSS وWeb Animations API و`IntersectionObserver` دون أي مكتبة حركة خارجية.
- **الخادم:** Node.js + Express، واجهة REST، وجلسات مُخزَّنة على الخادم. يقدّم الخادم ناتج بناء Vite من `frontend/dist` مع الحفاظ على صرامة سياسة CSP (بدون سكربتات مضمّنة).
- **قاعدة البيانات:** SQLite عبر وحدة `node:sqlite` المدمجة في Node.js، مع ملف قاعدة بيانات دائم.
- **الاختبارات:** `node:test` + `supertest`، وتغطي المصادقة والصلاحيات والتحقق من المدخلات ودورة حياة الطلبات والأقسام والأخبار والبيانات التجريبية وتقديم واجهات SPA.

## التشغيل السريع

```bash
# 1) نسخ ملف الإعدادات
# PowerShell
Copy-Item .env.example backend/.env
# Bash
cp .env.example backend/.env

# 2) تثبيت الاعتماديات وبناء الواجهة
cd frontend
npm install
npm run build

# 3) تثبيت اعتماديات الخادم
cd ../backend
npm install

# 4) تهيئة قاعدة البيانات + إنشاء حساب إداري + إضافة البيانات التجريبية
npm run setup

# 5) تشغيل الخادم
npm start
```

ثم افتح:

- الموقع: <http://127.0.0.1:3000>
- لوحة التحكم: <http://127.0.0.1:3000/admin>

في بيئة التطوير، إن لم يكن `SESSION_SECRET` مضبوطًا، يُولَّد سر عشوائي عند كل تشغيل (تنتهي الجلسات عند إعادة التشغيل). في الإنتاج يجب ضبطه إلزاميًا.

### إنشاء حساب إداري

```bash
cd backend
npm run admin:init
```

يقرأ الأمر `ADMIN_USERNAME` و`ADMIN_EMAIL` و`ADMIN_PASSWORD` من `backend/.env`. إذا كان `ADMIN_PASSWORD` فارغًا، يُولَّد كلمة مرور قوية وتُطبع مرة واحدة فقط. لا تُحفظ كلمة المرور كنص صريح؛ يُخزَّن تجزئتها باستخدام bcrypt.

### إعادة ضبط البيانات التجريبية

البيانات التجريبية **لا تُضاف تلقائيًا عند تشغيل الخادم**. تُدار صراحةً من:

- صفحة **البيانات التجريبية** في لوحة التحكم، أو
- واجهة الإدارة:

| العملية | الطلب | التأكيد المطلوب |
| --- | --- | --- |
| إضافة الناقص فقط (آمنة وقابلة للتكرار) | `POST /api/admin/demo-data/seed` | لا يوجد |
| حذف التجريبي وإعادة إنشائه | `POST /api/admin/demo-data/reset` | `{ "confirm": "RESET_DEMO_DATA" }` |
| حذف التجريبي دون إعادة إنشاء | `POST /api/admin/demo-data/cleanup` | `{ "confirm": "DELETE_DEMO_DATA" }` |

كل الطلبات تتطلب جلسة إدارية ورمز CSRF. عمليات البيانات التجريبية لا تمس السجلات الحقيقية. القسم التجريبي المرتبط بطلب حقيقي يُؤرشف بدلًا من حذفه، وتُعيد عملية `reset` نشره تلقائيًا. أما الحذف الإداري المباشر (طلب أو خبر أو قسم) فمتاح بالكامل من لوحة التحكم بعد تأكيد كتابي.

## النشر على Render أو Railway

المشروع جاهز للنشر على أي منصة تدعم Node.js. قاعدة البيانات ملف SQLite، لذلك النشر **مع قرص تخزين دائم** (Persistent Disk / Volume) هو الوضع الموصى به: بدونه تُفقد البيانات عند كل إعادة نشر.

- ملف `render.yaml` يجهّز خدمة Render كاملة (بناء، تشغيل، فحص صحة، متغيرات بيئة) على الخطة المجانية.
- ملف `railway.toml` يجهّز أوامر البناء والتشغيل على Railway.
- ملف `.node-version` يثبّت Node.js 24.

الدليل الكامل خطوة بخطوة، بما فيه متغيرات البيئة والقرص الدائم والخطة المجانية والنسخ الاحتياطي وحل المشكلات، في [`docs/DEPLOY.md`](docs/DEPLOY.md).

باختصار:

```text
Build:  cd frontend && npm ci && npm run build && cd ../backend && npm ci --omit=dev
Start:  cd backend && npm run admin:init && npm start
Health: /api/health
```

> يتطلب النشر بناء الواجهة أولًا. إذا كان المضيف يشغّل أمرًا واحدًا فقط، استخدم `npm ci && npm run build` داخل `frontend` قبل تثبيت اعتماديات الخادم، كما في `render.yaml` و`railway.toml`.

| الوضع | القرص | البيانات |
| --- | --- | --- |
| مجاني (Render Free) | بدون قرص، `DB_PATH=./data/taiba.sqlite` | تُعاد للبيانات التجريبية عند كل إعادة تشغيل |
| دائم (Render Starter / Railway Hobby) | `/var/data`، `DB_PATH=/var/data/taiba.sqlite` | محفوظة دائمًا |

> بعد أول نشر، افتح لوحة التحكم وغيّر كلمة مرور المدير، ثم احذف البيانات التجريبية قبل الإطلاق الرسمي.

## أوامر npm

من داخل مجلد `backend`:

| الأمر | الوظيفة |
| --- | --- |

## الأمان

- **كلمات المرور:** تجزئة bcrypt، ومقارنة ثابتة زمنيًا حتى للحسابات غير الموجودة.
- **الجلسات:** مخزَّنة على الخادم في SQLite، كوكي `HttpOnly` + `SameSite=Lax` + `Secure` في الإنتاج، وتجديد معرف الجلسة عند الدخول لمنع session fixation.
- **CSRF:** آلية double-submit عبر كوكي `taiba.csrf` ورأس `x-csrf-token` لكل طلب يغيّر الحالة.
- **الصلاحيات:** كل مسار إداري يمر عبر `requireAdmin`، ثم `requireCsrf`، ثم التحقق من المدخلات.
- **التحقق:** مخططات Zod على الخادم لكل حقل، مع رسائل عربية وحدود أطوال. روابط الصور ترفض `//host` والشرطة العكسية والمسافات.
- **قاعدة البيانات:** استعلامات مُعاملة (parameterized) فقط، وقيود FK، وحذف مرتبط محمي افتراضيًا، مع تأكيد كتابي قبل الحذف الكامل. رسالة التكرار العامة لا تكشف رقم الطلب السابق.
- **الحدود:** حد لحجم JSON والنماذج وعدد الحقول، وحدود معدل لتسجيل الدخول ونموذج التقديم تُحتسب فيها المحاولات الناجحة أيضًا. محرك استعلامات Express مضبوط على `simple` لتقليل سطح هجمات prototype pollution.
- **رفع الصور:** يُقبل JPG/PNG/WebP/GIF فقط (لا SVG)، بحد 5 ميجابايت للصورة و6 صور في الطلب، وتُولَّد أسماء الملفات على الخادم. تُفحص **magic bytes** الفعلية لكل ملف، وتُحذف الملفات غير الصالحة وغير المستخدمة تلقائيًا.
- **التصدير:** تصدير CSV يحيّد صيغ Excel/Sheets (CSV Formula Injection) ببادئة `'`.
- **الفيديو:** روابط فقط (YouTube أو Vimeo أو ملف MP4/WebM مباشر)، وتُحوَّل روابط YouTube إلى نطاق `youtube-nocookie.com`، مع تقييد `frame-src` في CSP على مزوّدي الفيديو المدعومين.
- **الرؤوس:** CSP صارم بلا سكربتات أو أنماط مضمّنة، و`frame-ancestors 'none'`، و`nosniff`، وسياسة مرجع آمنة، و`Permissions-Policy` لتعطيل القدرات الحساسة، و`Cache-Control: no-store` لكل استجابات `/api`. في الإنتاج يُعاد توجيه `http` إلى `https` تلقائيًا حتى تعمل كوكي `Secure` ولا تُرسل بيانات الدخول نصيًا.
- **الخصوصية:** واجهة المتقدم لا تُعيد الملاحظات الإدارية ولا المعرفات الداخلية، والملاحظات الداخلية لا تظهر في أي استجابة عامة.
- **الأخطاء:** رسائل آمنة بلا تفاصيل داخلية أو آثار مكدس في الإنتاج.

التفاصيل في [`docs/SECURITY.md`](docs/SECURITY.md).

## الهوية البصرية

تعتمد الواجهة العامة ولوحة التحكم هوية من ثلاثة ألوان أساسية — الأحمر والأزرق والأصفر —
مع الأبيض والخلفية الفاتحة كأسطح محايدة فقط. الألوان معرّفة كمتغيرات CSS في
`frontend/src/styles/website.css` و`frontend/src/styles/admin.css`:

| اللون | الدور |
| --- | --- |
| الأزرق الداكن `#062B4D` | اللون الأساسي للواجهة والنصوص والعناوين والأسطح الداكنة |
| الأزرق الأعمق `#041B33` | أعمق درجة في التدرجات وخلفيات الفوتر والهيرو |
| الأزرق الملكي `#0A3B66` / `#1769AA` | التدرجات والروابط والعناصر التفاعلية والرسوم |
| الأحمر `#D62839` | الأزرار الرئيسية والتنبيهات الحرجة والإجراءات المهمة |
| الأحمر العميق `#B01E2C` | نهاية تدرّج الأزرار والتحويم والدرجة النصّية للقراءة |
| الأصفر `#FFC928` | التمييز والشارات واللمسات الفاخرة والحدود المضيئة |
| الأصفر الفاتح `#FFD75E` | تدرّجات التوهج واللمعان |
| الأبيض `#FFFFFF` | الأسطح والبطاقات والنصوص على الداكن |
| الخلفية الفاتحة `#F5F8FC` | خلفية الصفحات العامة ولوحة التحكم |

- التدرجات الرسمية: `--gradient-brand` (أزرق ← أحمر)، `--gradient-warm` (أصفر ← أحمر)، `--gradient-cta` (أحمر ← أحمر عميق)، و`--gradient-surface` (أبيض ← أزرق فاتح).
- الهيدر وشريط الإحصائيات وبطاقات الـKPI تستخدم زجاجية خفيفة (`backdrop-filter` + شفافية)، مع توهجات ناعمة بالظلال بدل الحدود الثقيلة.
- الأحمر درجة واحدة أساسية مع درجة عميقة للتحويم والنص، والأصفر يُستخدم خلفيةً مع نص داكن فقط، حفاظًا على تباين كافٍ.
- لا تُستخدم عائلة لونية رابعة: حالات النجاح تظهر بالأزرق، والتحذير بالأصفر، والخطأ بالأحمر.
- الزخرفة الإسلامية (نجمة ثمانية) محفوظة كخلفية SVG مضمّنة بألوان الأزرق الملكي والأصفر وبشفافية منخفضة.
- الحركة تعتمد CSS وCanvas و`IntersectionObserver` و`requestAnimationFrame` فقط، وتُعطَّل تلقائيًا مع `prefers-reduced-motion`. لم تُضف مكتبات حركة تكتب أنماطًا مضمّنة (مثل GSAP أو Framer Motion)، التزامًا بسياسة CSP الصارمة (`style-src 'self'`) وتجنّبًا لحجم غير ضروري؛ الاستثناء الوحيد هو Three.js/R3F للهيرو ثلاثي الأبعاد كما هو موضح أدناه، ويُحمّل كقطعة منفصلة عند الحاجة فقط.
- جميع الأيقونات والرسوم SVG أصلية داخل المشروع، ولا تُستخدم صور مدرسية أو شعارات جهات حقيقية.

### طبقة التجربة المميّزة (Signature layer)

أُضيفت في الإصدار 3.0.0 كطبقة بصرية فوق المكوّنات القائمة دون تغيير بياناتها أو سلوكها، وتتكوّن من:

| الملف | الوظيفة |
| --- | --- |
| `src/styles/signature.css` | طبقة التصميم النهائية: تدرّجات، زجاج، حلقات، وميض، وحالات تحويم لكل الصفحات. تُستورد بعد `website.css` و`motion.css`. |
| `components/public/experience/HeroAtmosphere.jsx` | لوحة جسيمات حيّة على Canvas بألوان اللوجو، مع تفاعل خفيف مع المؤشر وإيقاف تلقائي عند إخفاء التبويب أو تفعيل تقليل الحركة. |
| `components/public/experience/ScrollProgress.jsx` | شريط تقدّم القراءة أعلى الصفحة؛ يستخدم CSS scroll timeline مع بديل يعتمد على خاصية `data-step` (لا أنماط مضمّنة). |
| `components/public/experience/IntroSplash.jsx` | شاشة دخول سينمائية تظهر مرة واحدة لكل تبويب عند فتح الموقع، وتتلاشى بأنimation خروج ثم تُزال، مع احترام `prefers-reduced-motion`. |
| `components/public/experience/BrandTicker.jsx` | شريط كلمات متحرك يفصل بين الهيرو وبقية الصفحة الرئيسية. |
| `components/public/experience/SplitWords.jsx` | ظهور كلمة بكلمة لعنوان الهيرو بتتابع CSS. |

الهيدر والفوتر وبطاقات الصفحات الداخلية وحالات الأقسام استلمت لمسات من هذه الطبقة، بما فيها إضاءة أشعة الهيرو، وتوهّج العناوين وحافة الفوتر، وتفاعل موحّد لكل الأيقونات عند التحويم والتركيز. بينما بقيت نماذج التقديم والصلاحيات وواجهات API كما هي تمامًا.

### طبقة السينما والثلاثي الأبعاد (Cinematic layer)

أُضيفت كطبقة ثانية فوق Signature layer، وتركّز على الحركة والعمق دون تغيير أي بيانات أو منطق:

| الملف | الوظيفة |
| --- | --- |
| `src/styles/cinematic.css` | انتقالات صفحة سينمائية (ستار + طمس وتكبير)، ظهور الأقسام عند التمرير، مغناطيسية الأزرار، ميل البطاقات ثلاثي الأبعاد، توهّج المؤشر على سطح المكتب، قائمة تنقّل متحركة، ومؤشر تقدّم بصري لنموذج التقديم. |
| `src/styles/admin-cinematic.css` | لمسات بصرية فقط للوحة التحكم: Sidebar زجاجي، بطاقات KPI متوهجة، صفوف جداول متحركة، وحالات تركيز أوضح. الصلاحيات والـCSV والـCSRF لم تتغيّر. |
| `src/lib/cinematic.js` | مستمع مؤشر واحد لكامل المستند يكتب متغيرات CSS عبر `style.setProperty` (لا أنماط مضمّنة)، مع حارس `IntersectionObserver` وفاحص هندسي احتياطي يضمن ألا يبقى أي قسم مخفيًا. |
| `components/public/experience/HeroExperience.jsx` | بوابة WebGL: تُحمّل المشهد ثلاثي الأبعاد كسلة منفصلة فقط على شاشات سطح المكتب التي تدعم WebGL ولا تُفعّل تقليل الحركة، وتسقط تلقائيًا إلى الـCanvas ثنائي الأبعاد الأصلي عند أي فشل. |
| `components/public/experience/HeroScene3D.jsx` | مشهد R3F حقيقي: نواة معرفية متعددة السطوح، حلقات مدارية، شظايا تقنية، وحقل جسيمات بألوان المجمع. هندسة منخفضة، بلا shadow maps، وDPR محدود بـ1.5. |
| `components/public/experience/CinematicCursor.jsx` | توهّج مؤشر خفيف لمؤشرات الفأرة الدقيقة فقط، مع إبقاء المؤشر الأصلي لأسباب الوصولية. |
| `components/public/experience/ApplicationProgress.jsx` | مؤشر اكتمال بصري لنموذج القبول ( `role="progressbar"` ) من غير تعديل التحقق أو بيانات الإرسال أو رفع المستندات الثلاثة. |

التبعيتان الجديدتان `three@^0.187.0` و`@react-three/fiber@^9.8.2` متوافقتان مع React 19.3.1 وتُستخدمان محليًا فقط؛ لا يوجد أي سكربت أو خط أو صورة من مصدر خارجي، لذلك تبقى CSP سليمة. ملف 3D منفصل بحجم ≈935 كيلوبايت (≈250 كيلوبايت مضغوط) لا يُنزّل أبدًا على الهاتف أو عند تقليل الحركة. شاشة الافتتاحية أصبحت قابلة للتخطي بزر «تخطي الافتتاحية» أو بمفتاح Escape/Enter.

### التخصصات المهنية الحقيقية

أُضيفت 17 تخصصًا مهنيًا من قائمة مجمع طيبة تكنولوجي ببنى سويف، مع وصف عربي ومجال تركيز ومهارات ومعلومات تقديم لكل تخصص. البيانات في `backend/src/db/real-departments-data.js`، وتُزرع عبر `npm run db:seed:real` كسجلات حقيقية (`is_demo = 0`). يقوم الباذر كذلك بإخفاء الأقسام التجريبية العشرة عن الموقع العام، مع الإبقاء عليها في لوحة التحكم حتى لا تتأثر الاختبارات أو سجلات التقديم القديمة.

القائمة تشمل: خراطة المعادن، لحام المعادن، الألومتال، التبريد والتكييف، شبكات الحاسب، المواسير الصناعية والصحية، الأجهزة المنزلية، الكهربية، ماكينات اليورش/الفرايز/المقاشط، الملابس الجاهزة، الإلكترونيات الصناعية، الأنظمة المدمجة والذكاء الاصطناعي، برمجة الحاسب، الأجهزة الطبية، المعمل الكيميائي، ومخارط وفرايز CNC. استُبعد آخر تخصصين من القائمة الأصلية حسب طلب المركز.

### الخطة الدراسية الحقيقية (المواد)

أُضيفت **69 مادة دراسية** تغطي ١١ قسمًا من الأقسام المطلوبة عبر الصفوف الأول والثاني والثالث. البيانات في `backend/src/db/real-subjects-data.js`، وتُزرع عبر `npm run db:seed:subjects`.

- المواد العامة (عربي، إنجليزي، رياضة، ميكا، معلومات، دين، جودة، ريادة، تكنولوجيا) تُخزَّن مرة واحدة لكل صف، وتظهر مع كل التخصصات كما صممت واجهة `/api/subjects` أصلًا.
- المواد التخصصية مرتبطة بالتخصص المناسب. قائمة «مواسير وتبريد وألوميتال ولحام» طُبِّقت على الأقسام الأربعة الموجودة: المواسير، التبريد والتكييف، الألومتال، ولحام المعادن.
- الأرقام التي أرسلها المركز تُخزَّن في العمود `weekly_periods` وتظهر على بطاقة المادة في الموقع العام وفي لوحة التحكم، ويمكن تعديلها من نموذج المادة.
- الباذر يخفي المواد التجريبية الثمانية ولا يحذفها، تمامًا كما فعل باذر التخصصات.

> ملاحظة: الأقسام التي لم ترد لها قائمة مواد في القائمة المرسلة (ماكينات الورشة، مخارط CNC، فرايز CNC) تعرض حاليًا المواد العامة فقط للصف المختار.

## القيود المعروفة

- لا يوجد إرسال بريد إلكتروني أو رسائل SMS؛ حالة الطلب تُدار داخل لوحة التحكم فقط.
- لا يوجد رفع مرفقات لطلبات التقديم؛ رفع الصور متاح فقط لوسائط الأخبار من لوحة التحكم.
- لا يوجد استعادة كلمة مرور أو مصادقة ثنائية أو أدوار متعددة؛ الحساب الإداري واحد بدور كامل.
- SQLite مناسب لهذا الحجم، لكنه ليس خيارًا للتوسع الأفقي الكبير.
- تصدير CSV يُبنى في الذاكرة، وهو مناسب لآلاف السجلات لا لملايينها.
- لا توجد نسخ احتياطي تلقائي؛ يجب نسخ ملف قاعدة البيانات دوريًا.
- لا يوجد سجل تدقيق (audit log) لتغييرات الإدارة.
- الإعدادات جاهزة للتطوير والتشغيل المحلي، وتحتاج مراجعة نشر (HTTPS، وكيل عكسي، نسخ احتياطي، مراقبة) قبل الإنتاج الفعلي.
