# مدرسة طيبة تكنولوجي — الموقع ولوحة التحكم

موقع تعريفي عربي (RTL) لمدرسة تقنية، مع لوحة تحكم إدارية آمنة لإدارة الأقسام وطلبات التقديم والأخبار (بما فيها الصور المرفوعة وروابط الفيديو) والمحتوى والبيانات التجريبية.

- **الواجهة العامة:** HTML5 + CSS3 + JavaScript حديث (ES Modules) مع `fetch`، دون أي إطار عمل أو اعتماد على CDN.
- **الخادم:** Node.js + Express، واجهة REST، وجلسات مُخزَّنة على الخادم.
- **قاعدة البيانات:** SQLite عبر وحدة `node:sqlite` المدمجة في Node.js، مع ملف قاعدة بيانات دائم.
- **الاختبارات:** `node:test` + `supertest`، وتغطي المصادقة والصلاحيات والتحقق من المدخلات ودورة حياة الطلبات والأقسام والأخبار والبيانات التجريبية.

## التشغيل السريع

```bash
# 1) نسخ ملف الإعدادات
# PowerShell
Copy-Item .env.example backend/.env
# Bash
cp .env.example backend/.env

# 2) تثبيت الاعتماديات
cd backend
npm install

# 3) تهيئة قاعدة البيانات + إنشاء حساب إداري + إضافة البيانات التجريبية
npm run setup

# 4) تشغيل الخادم
npm start
```

ثم افتح:

- الموقع: <http://127.0.0.1:3000>
- لوحة التحكم: <http://127.0.0.1:3000/admin>

في بيئة التطوير، إن لم يكن `SESSION_SECRET` مضبوطًا، يُولَّد سر عشوائي عند كل تشغيل (تنتهي الجلسات عند إعادة التشغيل). في الإنتاج يجب ضبطه إلزاميًا.

### إنشاء حساب إداري

```bash
cd backend
npm run admin:init
```

يقرأ الأمر `ADMIN_USERNAME` و`ADMIN_EMAIL` و`ADMIN_PASSWORD` من `backend/.env`. إذا كان `ADMIN_PASSWORD` فارغًا، يُولَّد كلمة مرور قوية وتُطبع مرة واحدة فقط. لا تُحفظ كلمة المرور كنص صريح؛ يُخزَّن تجزئتها باستخدام bcrypt.

### إعادة ضبط البيانات التجريبية

البيانات التجريبية **لا تُضاف تلقائيًا عند تشغيل الخادم**. تُدار صراحةً من:

- صفحة **البيانات التجريبية** في لوحة التحكم، أو
- واجهة الإدارة:

| العملية | الطلب | التأكيد المطلوب |
| --- | --- | --- |
| إضافة الناقص فقط (آمنة وقابلة للتكرار) | `POST /api/admin/demo-data/seed` | لا يوجد |
| حذف التجريبي وإعادة إنشائه | `POST /api/admin/demo-data/reset` | `{ "confirm": "RESET_DEMO_DATA" }` |
| حذف التجريبي دون إعادة إنشاء | `POST /api/admin/demo-data/cleanup` | `{ "confirm": "DELETE_DEMO_DATA" }` |

كل الطلبات تتطلب جلسة إدارية ورمز CSRF. عمليات البيانات التجريبية لا تمس السجلات الحقيقية. القسم التجريبي المرتبط بطلب حقيقي يُؤرشف بدلًا من حذفه، وتُعيد عملية `reset` نشره تلقائيًا. أما الحذف الإداري المباشر (طلب أو خبر أو قسم) فمتاح بالكامل من لوحة التحكم بعد تأكيد كتابي.

## النشر على Render أو Railway

المشروع جاهز للنشر على أي منصة تدعم Node.js. قاعدة البيانات ملف SQLite، لذلك النشر **مع قرص تخزين دائم** (Persistent Disk / Volume) هو الوضع الموصى به: بدونه تُفقد البيانات عند كل إعادة نشر.

- ملف `render.yaml` يجهّز خدمة Render كاملة (بناء، تشغيل، فحص صحة، متغيرات بيئة) على الخطة المجانية.
- ملف `railway.toml` يجهّز أوامر البناء والتشغيل على Railway.
- ملف `.node-version` يثبّت Node.js 24.

الدليل الكامل خطوة بخطوة، بما فيه متغيرات البيئة والقرص الدائم والخطة المجانية والنسخ الاحتياطي وحل المشكلات، في [`docs/DEPLOY.md`](docs/DEPLOY.md).

باختصار:

```text
Build:  cd backend && npm ci --omit=dev
Start:  cd backend && npm run admin:init && npm start
Health: /api/health
```

| الوضع | القرص | البيانات |
| --- | --- | --- |
| مجاني (Render Free) | بدون قرص، `DB_PATH=./data/taiba.sqlite` | تُعاد للبيانات التجريبية عند كل إعادة تشغيل |
| دائم (Render Starter / Railway Hobby) | `/var/data`، `DB_PATH=/var/data/taiba.sqlite` | محفوظة دائمًا |

> بعد أول نشر، افتح لوحة التحكم وغيّر كلمة مرور المدير، ثم احذف البيانات التجريبية قبل الإطلاق الرسمي.

## الأمان

- **كلمات المرور:** تجزئة bcrypt، ومقارنة ثابتة زمنيًا حتى للحسابات غير الموجودة.
- **الجلسات:** مخزَّنة على الخادم في SQLite، كوكي `HttpOnly` + `SameSite=Lax` + `Secure` في الإنتاج، وتجديد معرف الجلسة عند الدخول لمنع session fixation.
- **CSRF:** آلية double-submit عبر كوكي `taiba.csrf` ورأس `x-csrf-token` لكل طلب يغيّر الحالة.
- **الصلاحيات:** كل مسار إداري يمر عبر `requireAdmin`، ثم `requireCsrf`، ثم التحقق من المدخلات.
- **التحقق:** مخططات Zod على الخادم لكل حقل، مع رسائل عربية وحدود أطوال.
- **قاعدة البيانات:** استعلامات مُعاملة (parameterized) فقط، وقيود FK، وحذف مرتبط محمي افتراضيًا، مع تأكيد كتابي قبل الحذف الكامل.
- **الحدود:** حد لحجم JSON والنماذج، وحدود معدل لتسجيل الدخول ونموذج التقديم.
- **رفع الصور:** يُقبل JPG/PNG/WebP/GIF فقط (لا SVG)، بحد 5 ميجابايت للصورة و6 صور في الطلب، وتُولَّد أسماء الملفات على الخادم. تُحذف الملفات غير المستخدمة تلقائيًا عند تحديث الخبر أو حذفه.
- **الفيديو:** روابط فقط (YouTube أو Vimeo أو ملف MP4/WebM مباشر)، وتُحوَّل روابط YouTube إلى نطاق `youtube-nocookie.com`، مع تقييد `frame-src` في CSP على مزوّدي الفيديو المدعومين.
- **الرؤوس:** CSP صارم بلا سكربتات أو أنماط مضمّنة، و`frame-ancestors 'none'`، و`nosniff`، وسياسة مرجع آمنة.
- **الخصوصية:** واجهة المتقدم لا تُعيد الملاحظات الإدارية ولا المعرفات الداخلية، والملاحظات الداخلية لا تظهر في أي استجابة عامة.
- **الأخطاء:** رسائل آمنة بلا تفاصيل داخلية أو آثار مكدس في الإنتاج.

التفاصيل في [`docs/SECURITY.md`](docs/SECURITY.md).

## متغيرات البيئة

انسخ `.env.example` إلى `backend/.env`. أهم المتغيرات:

| المتغير | الافتراضي | ملاحظات |
| --- | --- | --- |
| `NODE_ENV` | `development` | استخدم `production` في الإنتاج |
| `PORT` | `3000` | منفذ الخادم |
| `HOST` | `127.0.0.1` | عنوان الاستماع |
| `DB_PATH` | `../database/taiba.sqlite` | نسبي إلى `backend/` |
| `SEED_DEMO_ON_EMPTY` | `false` | تعبئة البيانات التجريبية عند إقلاع قاعدة فارغة (للاستضافة بلا قرص فقط) |
| `SESSION_SECRET` | فارغ | **إلزامي في الإنتاج** |
| `SESSION_TTL_HOURS` | `8` | مدة الجلسة |
| `TRUST_PROXY` | `false` | فعّلها فقط خلف وكيل موثوق |
| `ADMIN_USERNAME` / `ADMIN_EMAIL` | `admin` / `admin@taiba.demo` | للحساب الأول |
| `ADMIN_PASSWORD` | فارغ | اتركه فارغًا ليُولَّد تلقائيًا |
| `LOGIN_RATE_LIMIT_MAX` | `10` | محاولات الدخول لكل نافذة |
| `APPLICATION_RATE_LIMIT_MAX` | `5` | طلبات التقديم لكل نافذة |
| `NEWS_UPLOADS_DIR` | `frontend/website/assets/uploads/news` | مجلد صور الأخبار المرفوعة (نسبةً إلى `backend/` أو مسار مطلق) |
| `NEWS_UPLOAD_MAX_BYTES` | `5242880` | الحد الأقصى لحجم صورة الخبر بالبايت (5 ميجابايت) |
| `ALLOWED_ORIGINS` | فارغ | أصول إضافية مفصولة بفواصل |

> لا تضع أي أسرار حقيقية في `.env.example` أو في المستودع. ملف `backend/.env` مستثنى في `.gitignore`.

- التدرجات الرسمية: `--gradient-brand` (أزرق ← أحمر)، `--gradient-warm` (أصفر ← أحمر)، `--gradient-cta` (أحمر ← أحمر عميق)، و`--gradient-surface` (أبيض ← أزرق فاتح).
- الهيدر وشريط الإحصائيات وبطاقات الـKPI تستخدم زجاجية خفيفة (`backdrop-filter` + شفافية)، مع توهجات ناعمة بالظلال بدل الحدود الثقيلة.
- الأحمر درجة واحدة أساسية مع درجة عميقة للتحويم والنص، والأصفر يُستخدم خلفيةً مع نص داكن فقط، حفاظًا على تباين كافٍ.
- لا تُستخدم عائلة لونية رابعة: حالات النجاح تظهر بالأزرق، والتحذير بالأصفر، والخطأ بالأحمر.
- الزخرفة الإسلامية (نجمة ثمانية) محفوظة كخلفية SVG مضمّنة بألوان الأزرق الملكي والأصفر وبشفافية منخفضة.
- الحركة تعتمد CSS و`IntersectionObserver` فقط، وتُعطَّل تلقائيًا مع `prefers-reduced-motion`، ولا تعتمد على أي مكتبة خارجية.
- جميع الأيقونات والرسوم SVG أصلية داخل المشروع، ولا تُستخدم صور مدرسية أو شعارات جهات حقيقية.

## القيود المعروفة

- لا يوجد إرسال بريد إلكتروني أو رسائل SMS؛ حالة الطلب تُدار داخل لوحة التحكم فقط.
- لا يوجد رفع مرفقات لطلبات التقديم؛ رفع الصور متاح فقط لوسائط الأخبار من لوحة التحكم.
- لا يوجد استعادة كلمة مرور أو مصادقة ثنائية أو أدوار متعددة؛ الحساب الإداري واحد بدور كامل.
- SQLite مناسب لهذا الحجم، لكنه ليس خيارًا للتوسع الأفقي الكبير.
- تصدير CSV يُبنى في الذاكرة، وهو مناسب لآلاف السجلات لا لملايينها.
- لا توجد نسخ احتياطي تلقائي؛ يجب نسخ ملف قاعدة البيانات دوريًا.
- لا يوجد سجل تدقيق (audit log) لتغييرات الإدارة.
- الإعدادات جاهزة للتطوير والتشغيل المحلي، وتحتاج مراجعة نشر (HTTPS، وكيل عكسي، نسخ احتياطي، مراقبة) قبل الإنتاج الفعلي.
