# مدرسة طيبة تكنولوجي — الموقع ولوحة التحكم

موقع تعريفي عربي (RTL) لمدرسة تقنية، مع لوحة تحكم إدارية آمنة لإدارة الأقسام وطلبات التقديم والمحتوى والبيانات التجريبية.

- **الواجهة العامة:** HTML5 + CSS3 + JavaScript حديث (ES Modules) مع `fetch`، دون أي إطار عمل أو اعتماد على CDN.
- **الخادم:** Node.js + Express، واجهة REST، وجلسات مُخزَّنة على الخادم.
- **قاعدة البيانات:** SQLite عبر وحدة `node:sqlite` المدمجة في Node.js، مع ملف قاعدة بيانات دائم.
- **الاختبارات:** `node:test` + `supertest`، وتغطي المصادقة والصلاحيات والتحقق من المدخلات ودورة حياة الطلبات والأقسام والبيانات التجريبية.

## التشغيل السريع

```bash
# 1) نسخ ملف الإعدادات
# PowerShell
Copy-Item .env.example backend/.env
# Bash
cp .env.example backend/.env

# 2) تثبيت الاعتماديات
cd backend
npm install

# 3) تهيئة قاعدة البيانات + إنشاء حساب إداري + إضافة البيانات التجريبية
npm run setup

# 4) تشغيل الخادم
npm start
```

ثم افتح:

- الموقع: <http://127.0.0.1:3000>
- لوحة التحكم: <http://127.0.0.1:3000/admin>

في بيئة التطوير، إن لم يكن `SESSION_SECRET` مضبوطًا، يُولَّد سر عشوائي عند كل تشغيل (تنتهي الجلسات عند إعادة التشغيل). في الإنتاج يجب ضبطه إلزاميًا.

### إنشاء حساب إداري

```bash
cd backend
npm run admin:init
```

يقرأ الأمر `ADMIN_USERNAME` و`ADMIN_EMAIL` و`ADMIN_PASSWORD` من `backend/.env`. إذا كان `ADMIN_PASSWORD` فارغًا، يُولَّد كلمة مرور قوية وتُطبع مرة واحدة فقط. لا تُحفظ كلمة المرور كنص صريح؛ يُخزَّن تجزئتها باستخدام bcrypt.

### إعادة ضبط البيانات التجريبية

البيانات التجريبية **لا تُضاف تلقائيًا عند تشغيل الخادم**. تُدار صراحةً من:

- صفحة **البيانات التجريبية** في لوحة التحكم، أو
- واجهة الإدارة:

| العملية | الطلب | التأكيد المطلوب |
| --- | --- | --- |
| إضافة الناقص فقط (آمنة وقابلة للتكرار) | `POST /api/admin/demo-data/seed` | لا يوجد |
| حذف التجريبي وإعادة إنشائه | `POST /api/admin/demo-data/reset` | `{ "confirm": "RESET_DEMO_DATA" }` |
| حذف التجريبي دون إعادة إنشاء | `POST /api/admin/demo-data/cleanup` | `{ "confirm": "DELETE_DEMO_DATA" }` |

كل الطلبات تتطلب جلسة إدارية ورمز CSRF. البيانات الحقيقية لا تُحذف. القسم التجريبي المرتبط بطلب حقيقي يُؤرشف بدلًا من حذفه، وتُعيد عملية `reset` نشره تلقائيًا.

## أوامر npm

من داخل مجلد `backend`:

| الأمر | الوظيفة |
| --- | --- |
| `npm start` | تشغيل الخادم |
| `npm run dev` | تشغيل الخادم مع إعادة التشغيل التلقائي عند التعديل |

## الأمان

- **كلمات المرور:** تجزئة bcrypt، ومقارنة ثابتة زمنيًا حتى للحسابات غير الموجودة.
- **الجلسات:** مخزَّنة على الخادم في SQLite، كوكي `HttpOnly` + `SameSite=Lax` + `Secure` في الإنتاج، وتجديد معرف الجلسة عند الدخول لمنع session fixation.
- **CSRF:** آلية double-submit عبر كوكي `taiba.csrf` ورأس `x-csrf-token` لكل طلب يغيّر الحالة.
- **الصلاحيات:** كل مسار إداري يمر عبر `requireAdmin`، ثم `requireCsrf`، ثم التحقق من المدخلات.
- **التحقق:** مخططات Zod على الخادم لكل حقل، مع رسائل عربية وحدود أطوال.
- **قاعدة البيانات:** استعلامات مُعاملة (parameterized) فقط، وقيود FK، وحذف محمي للبيانات المرتبطة.
- **الحدود:** حد لحجم JSON والنماذج، وحدود معدل لتسجيل الدخول ونموذج التقديم.
- **الرؤوس:** CSP صارم بلا سكربتات أو أنماط مضمّنة، و`frame-ancestors 'none'`، و`nosniff`، وسياسة مرجع آمنة.
- **الخصوصية:** واجهة المتقدم لا تُعيد الملاحظات الإدارية ولا المعرفات الداخلية، والملاحظات الداخلية لا تظهر في أي استجابة عامة.
- **الأخطاء:** رسائل آمنة بلا تفاصيل داخلية أو آثار مكدس في الإنتاج.

التفاصيل في [`docs/SECURITY.md`](docs/SECURITY.md).

## متغيرات البيئة

انسخ `.env.example` إلى `backend/.env`. أهم المتغيرات:

| المتغير | الافتراضي | ملاحظات |
| --- | --- | --- |
| `NODE_ENV` | `development` | استخدم `production` في الإنتاج |
| `PORT` | `3000` | منفذ الخادم |
| `HOST` | `127.0.0.1` | عنوان الاستماع |
| `DB_PATH` | `../database/taiba.sqlite` | نسبي إلى `backend/` |
| `SESSION_SECRET` | فارغ | **إلزامي في الإنتاج** |
| `SESSION_TTL_HOURS` | `8` | مدة الجلسة |
| `TRUST_PROXY` | `false` | فعّلها فقط خلف وكيل موثوق |
| `ADMIN_USERNAME` / `ADMIN_EMAIL` | `admin` / `admin@taiba.demo` | للحساب الأول |
| `ADMIN_PASSWORD` | فارغ | اتركه فارغًا ليُولَّد تلقائيًا |
| `LOGIN_RATE_LIMIT_MAX` | `10` | محاولات الدخول لكل نافذة |
| `APPLICATION_RATE_LIMIT_MAX` | `5` | طلبات التقديم لكل نافذة |
| `ALLOWED_ORIGINS` | فارغ | أصول إضافية مفصولة بفواصل |

> لا تضع أي أسرار حقيقية في `.env.example` أو في المستودع. ملف `backend/.env` مستثنى في `.gitignore`.

## البيانات التجريبية

- 10 أقسام تعليمية بأسماء ووصفات ومهارات.
- 8 طلبات تقديم وهمية بأرقام مرجعية تبدأ بـ `DEMO-`.
- أسئلة شائعة ونصوص افتراضية للصفحات.
- كل السجلات موسومة بـ `is_demo = 1` لتمييزها عن البيانات الحقيقية.
- أسماء وأرقام الهواتف والبريد في البيانات التجريبية وهمية بالكامل، وليست جهات اتصال رسمية.

## القيود المعروفة

- لا يوجد إرسال بريد إلكتروني أو رسائل SMS؛ حالة الطلب تُدار داخل لوحة التحكم فقط.
- لا يوجد رفع ملفات أو مرفقات للطلبات.
- لا يوجد استعادة كلمة مرور أو مصادقة ثنائية أو أدوار متعددة؛ الحساب الإداري واحد بدور كامل.
- SQLite مناسب لهذا الحجم، لكنه ليس خيارًا للتوسع الأفقي الكبير.
- تصدير CSV يُبنى في الذاكرة، وهو مناسب لآلاف السجلات لا لملايينها.
- لا توجد نسخ احتياطي تلقائي؛ يجب نسخ ملف قاعدة البيانات دوريًا.
- لا يوجد سجل تدقيق (audit log) لتغييرات الإدارة.
- الإعدادات جاهزة للتطوير والتشغيل المحلي، وتحتاج مراجعة نشر (HTTPS، وكيل عكسي، نسخ احتياطي، مراقبة) قبل الإنتاج الفعلي.
